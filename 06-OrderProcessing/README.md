# نظام معالجة طلبات التجارة الإلكترونية — تخزين JSON

مشروع Console App باستخدام C# و.NET 10. لا يستخدم قاعدة بيانات حقيقية ولا خدمات خارجية؛ جميع الاتصالات ممثلة بواسطة `Task.Delay`، والتخزين الفعلي عبارة عن ملفات JSON محلية.

## المتطلبات

- .NET SDK 10.0
- Windows أو Linux أو macOS

## التشغيل

من داخل مجلد المشروع:

```bash
dotnet build
dotnet run -- phase1
dotnet run -- phase2
dotnet run -- phase3
dotnet run -- phase3 --cancel-after 4000
```

اضغط `Ctrl+C` لإلغاء التشغيل الحالي. يدعم الأمر أيضًا `dotnet run -- phase1 --sync-comparison` لمقارنة زمن استعلام العميل باستخدام `JsonFileStore` المتزامن وغير المتزامن؛ وضع المقارنة هذا لا يعالج الطلبات، بل يقيس استعلامات القراءة فقط.

عند كل تشغيل مرحلة، يتم تنفيذ `DataSeeder.ResetAsync()` أولًا. يبدأ عدّ `--cancel-after` بعد اكتمال إعادة التهيئة حتى تكون ملفات البداية موجودة وصحيحة.

## أماكن الملفات

يكتب البرنامج إلى:

```text
bin/Debug/net10.0/Data/
  customers.json
  products.json
  coupons.json
  incoming_orders.json
  orders.json
  payments.json
  emails.json
  email_retry.json
  invoices/
  reports/
```

مجلد `Data` ينشأ تلقائيًا عند التشغيل. ملفات البداية تُعاد إلى القيم المحددة في وصف المشروع في بداية كل Phase، بينما ملفات `orders.json` و`payments.json` و`emails.json` و`email_retry.json` تبدأ بمصفوفات فارغة `[]`.

## تصميم التخزين

- `JsonFileStore` هو الكلاس الوحيد الذي يقرأ ويكتب ملفات مجموعات JSON.
- جميع عمليات القراءة والتعديل غير المتزامنة تستقبل `CancellationToken`.
- `UpdateAsync` ينفذ read-modify-write داخل قفل واحد خاص بالملف لمنع فقد تحديثات بين المهام داخل العملية نفسها.
- الكتابة تتم في ملف مؤقت داخل المجلد نفسه، ثم يُستبدل الملف النهائي بعملية rename/replace؛ بذلك لا يظهر للقارئ ملف JSON نصف مكتوب.
- الملف غير الموجود يُقرأ كمجموعة فارغة، وJSON غير الصالح يؤدي إلى `DataFileCorruptedException` يتضمن اسم الملف.
- خيارات التسلسل مشتركة: `WriteIndented = true` و`camelCase` و`JsonStringEnumConverter`، والترميز UTF-8 دون BOM.
- ملفات الفواتير النصية والتقرير JSON هي الاستثناءات المسموح بها للكتابة خارج `JsonFileStore`.

## ما تنفذه المراحل

### Phase 1

معالجة الطلبات بالتتابع باستخدام `async/await`، مع التحقق من العملاء والمنتجات والكوبونات، وحجز المخزون، والتسعير والشحن والدفع، وحفظ الطلب، وإرسال التأكيد بالبريد.

### Phase 2

معالجة متوازية (حد أقصى 4 مهام)، وإنشاء فاتورة نصية لكل طلب مكتمل وإنشاء تقرير JSON في `reports/`. فشل التسعير المقصود للطلب رقم 7 يتم حقنه في هذه المرحلة.

### Phase 3

تشمل معالجة المرحلة الثانية، مع الحالات التجريبية التالية:

- الطلب 3: أول محاولتين للبريد تفشلان، والمحاولة الثالثة تنجح.
- الطلب 5: انتهاء مهلة بوابة الدفع، ويُحفظ الطلب على أنه `PaymentFailed` وتُحرر الكمية.
- الطلب 8: رفض الدفع، ويُحفظ سجل رفض الدفع وتُحرر الكمية.
- الطلب 13: فشل حفظ الطلب بعد تحصيل الدفع؛ تتم محاولة رد المبلغ وتحرير المخزون ثم حفظ حالة الفشل.
- الطلب 17: فشل البريد في المحاولات الثلاث؛ يُحفظ في `email_retry.json` ولا يتحول الطلب المكتمل إلى فشل بسبب البريد وحده.

يتنافس الطلبان 10 و11 على آخر وحدة من لوحة المفاتيح. يتم تحديث المخزون ذريًا على مستوى الملف، ولذلك لن ينجح حجز كلا الطلبين لنفس الوحدة.

## قواعد العمل والافتراضات المعلنة

الوصف المرسل يحدد أرقام التأخير لكنه لا يحدد معادلة سعر الشحن أو تفاصيل احتساب متوسط قيمة الطلب. لتكون النتائج محددة، يستخدم هذا التنفيذ شرائح شحن ثابتة بناءً على الوزن الإجمالي: حتى 1 كجم = 5، وأكثر من 1 وحتى 5 كجم = 10، وأكثر من 5 كجم = 20. الخصم يطبق كنسبة الكوبون على المجموع الفرعي قبل إضافة الشحن. متوسط قيمة الطلب في التقرير = إيرادات الطلبات المكتملة ÷ عدد الطلبات المكتملة. لا يضيف LoyaltyTier خصمًا إضافيًا لأن الوصف المرسل لا يقدم قاعدة حساب له.

## الإلغاء والتعويض

كل عامل يتوقف عن بدء طلب جديد بعد ملاحظة الإلغاء. الطلب الجاري يعالج `OperationCanceledException` ويستخدم مهلة تعويض مستقلة ومحدودة حتى لا يمنع الـ token الملغى تحرير المخزون أو رد دفعة محصلة أو حفظ الطلب. الطلب الملغى يُحفظ بحالة `Pending` و`FailureReason = "Cancelled"`. يطبع التشغيل الملغى ملخصًا بالصيغة المطلوبة: `Run cancelled — {n} orders finished, {m} cancelled`.

## ملاحظات

- أقفال `JsonFileStore` تحمي التحديثات المتزامنة بين المهام داخل نسخة التطبيق نفسها. لا يدعي التنفيذ توفير قفل موزع بين عمليات نظام تشغيل مختلفة.
- لم يُنفذ بناء فعلي في بيئة إعداد المشروع الحالية لأن .NET SDK غير متوفر فيها؛ شغّل `dotnet build` محليًا قبل التسليم النهائي الأكاديمي.
